# 固定装备与练级节奏（2026-09-22）

同名装备的基础战斗属性一致，不再抽取随机数值、随机词缀或品质战斗倍率。品质仍决定颜色、孔数及售价；已镶嵌宝石额外加成完整保留。旧角色等级、累计经验、加点、技能、货币和物品身份不重置。

## 固定属性表

`database/seeders/Game/Data/items.php` 是最终目录入口，经 `FixedEquipmentStats::apply()` 生成固定数值；子目录中的历史原始数值不应直接用于生成物品。展开后的 104 件装备见 [完整属性表](balance/fixed-equipment-catalog.json)。

按每个部位的不同需求等级从低到高编号为 r，同等级共用主属性。相邻档的主属性增加 0–2 点；首饰部分档位主属性持平，保留部分装备的暴击、暴伤或法力特点。

| 部位 | 固定属性 |
| --- | --- |
| 武器 | 攻击 r，范围 1–14 |
| 法袍 | 防御 2r−1，范围 1–13；生命 2r+1；法力 2r |
| 头饰 | 防御 r；生命 2r；法力 r |
| 手套 | 防御 r；法力 r |
| 靴子 | 防御 r；生命 r |
| 腰带 | 生命 2r；法力 r |
| 戒指、护符 | 攻击 ceil(r/2)；保留原有特征属性，暴击最多 4%、暴伤最多 12% |

例如橡木法杖攻击 2、水晶法杖 3、月华法杖 4；流风法杖固定攻击 12。武器颜色或重复掉落不会改变这些基础数值。宝石属性另加，药水及已有宝石不在装备重算范围内。

## 线上原因与修正

只读 PostgreSQL 审计按 UTC 统计：主角色在普通难度末图 24 小时获得约 9,000 万经验，期间总承伤为 0；到 200 级累计需求仅 132,335,000。角色攻击 454、防御 686，普通怪物生命 162–243、攻击最高 120。旧装备品质倍率 1–2.5 倍再叠加随机数值与词缀，超过怪物的线性成长；平减防御使怪物完全无法造成伤害。

队列推进约 3.101 秒一次，测试模式关闭，未领取离线奖励；没有发现队列异常加速。日志仅保留 24 小时，不能据此重建角色从创建到满级的全部耗时。

另外修正独立的高难度经验重复加成：生成怪物时已经乘过难度奖励，结算时不再重复相乘。旧痛苦 6 的 14 倍曾叠成 196 倍；它不是这名普通难度角色的直接原因。金币仍只应用一次倍率。

固定装备后同步调整 123 只怪物的攻击、防御与经验，保留 41 张地图及怪物的 ID、名称与分布。精英和 Boss 采用坦克原型和各自倍率，避免原先小血量精英奖励过高。强怪保留 5% 原攻击的伤害下限（取整后弱怪仍可被完全格挡，新手营地攻击仍为 0），并降低每轮生命、法力自动恢复系数。离线经验速率从每级每秒 0.2 调为 0.02。

## 约一个月的口径与复现

目标是新角色在**普通难度持续挂机**约一个月到 200 级，按合适地图、及时换装与加点估算，不是每天只玩少量时间，也不是保证每个流派完全相同的耗时。旧累计经验曲线 `每级 50 × 当前等级²` 保持不变。经验主要由 `game.monster_progression.experience_scale = 0.1` 校准。

模拟脚本直接使用实际 `CombatRoundProcessor`、技能、状态效果及奖励结算；装备和怪物取最终目录，测试模式关闭，不连接或修改数据库。分别检查 13 个等级节点的 41 张地图，每张最多 600 轮，死亡即停止，选择存活地图中经验效率最高者。采用无宝石装备、50% 攻击/30% 体力/20% 能量加点及脚本列明的技能顺序。按 3 秒一轮、95% 普通怪、现有补怪概率和 60 秒刷新构造遭遇；不模拟寻装耗时、药水消费或玩家具体操作。

```sh
php scripts/benchmark-fixed-equipment.php --output=docs/balance/fixed-equipment-v1.json
```

本次估算 1→200 级为 **28.24–34.3 天**（连续普通挂机、无宝石），符合约一个月的目标；精确节点结果见 [时长估算](balance/leveling-projection.json)。

各等级经验速率使用节点间线性插值（及时调整地图和成长），或保持上一节点速率（较少调整）估算。对 1–199 级求和 `50 × level² / xpPerHour`，再乘线上实测 `3.101 / 3` 的推进时间比例。它是数值模型估计，并非实际跑满一个月；宝石、不同加点/技能、高难度和地图选择均会影响结果。原始采样数据见 [模拟结果](balance/fixed-equipment-v1.json)。

## 迁移与恢复

部署脚本先进入维护模式、停止队列及 Reverb，然后迁移：

1. 将装备定义、全部物品、镶嵌关系、装备槽、角色、地图与怪物逐行写入 `storage/app/upgrade-backups/fixed-gear-v1-*.json.gz`，权限 0600。写入失败则停止。
2. 通过规范化图标匹配固定目录，未知装备定义会停止升级。事务内更新定义、背包/仓库/已穿戴物品的属性，移除随机词缀并重算售价；保留品质、孔数、宝石、数量、位置与 ID。
3. 同步怪物，失败则回滚；取消角色的旧自动战斗任务，清理缓存敌人与技能冷却，HP/MP 超过新上限的部分收回。已死亡角色维持 HP 0。
4. 部署完成后由玩家重新开始战斗。迁移可重复执行，不会重复创建或删除物品。

随机旧词缀不可凭公式重建，migration 的 `down()` 不自动恢复。需要恢复时先维护停写、保留当前数据，再从上述升级前备份按主键恢复受影响字段，并切回对应旧代码/配置；不要在已经继续游玩后直接覆盖整张表，以免丢失后续进度。回滚代码的发布脚本不会自动回滚数据。

## 验证

- 额外对 15、65、100、199 级的候选地图各跑 3,000 轮，全部存活。经验速率与短样本接近，记录见 [延长模拟](balance/fixed-equipment-long-run.json)。
- 完整后端测试 62 项、2,145 次断言通过，包括跨品质重复掉落相等、宝石保留、迁移幂等、未匹配定义停止、怪物同步失败回滚、高难度经验只加成一次。
- 使用只读线上快照，在隔离 PostgreSQL 14.21 演练：104 个装备定义、444 件装备重算；其余 11 件宝石/药水保留，14 个镶嵌关系及 112 行装备槽关系不变。所有物品 ID、角色等级/经验/货币/点数保持一致，备份内容与迁移前逐字段相同，重复迁移结果一致。线上为 PostgreSQL 18，发布后另行核对实际数据。
- [演练记录](balance/rehearsal.json) 不包含玩家私密快照；原始快照仅位于本机临时目录，未纳入 Git。
- 前端大图修复独立发布为 `41924d5`，已在 320/390/1440 宽度验证比较两侧、已装备详情、像素 PNG、关闭返回及无溢出。数值展示直接读取 API 属性，不额外乘品质倍率。
